# Path Discovery

Use when the outcome is understandable but the route is unknown, contested, or risky.

## Method

1. Restate the outcome in tool-neutral language.
2. Inventory relevant current assets, constraints, skills, budget/credits, time, quality bar, and existing work.
3. Generate 2–4 routes only when there is a meaningful choice.
4. Compare routes by:
   - fidelity to outcome;
   - controllability;
   - complexity;
   - cost/credits;
   - iteration speed;
   - asset requirements;
   - failure modes;
   - reversibility.
5. Recommend one route when evidence allows.
6. Turn the route into stages.
7. Only then ask route-specific requirement questions.

## Research rule

If the recommendation depends on current platform/model/tool capabilities, verify those capabilities from reliable current documentation before locking the path.

## Anti-interrogation rule

User ignorance of the path is not missing user preference.

Bad:
“请选择结构参考、运动参考还是镜头参考。”

Better:
“你真正需要保住的是机位和人物动线，因此我建议把这份参考用于结构/运动控制；人物外观交给角色图。你只需要决定节奏是否也必须严格复现。”
