# Requirement Compiler v0.3 中文说明

Requirement Compiler 不是“高级提示词生成器”。它解决的是 Prompt 之前的问题：**用户可能知道自己最终想得到什么，但不知道实现路径、缺哪些关键条件，或者在多轮失败后上下文已经被旧假设污染。**

核心流程是：

**目标 Goal → 路径 Path → 当前需求 Spec → 执行 Execute → 诊断 Diagnose**

## 它应该怎样和你协作

你仍然可以直接语音说话，不需要提前整理成专业 Prompt。

它会先判断当前属于哪一类情况：

- `DIRECT`：已经很清楚，直接做；
- `EXPLORE_GOAL`：你连最终想达到什么都还没有完全定义；
- `DISCOVER_PATH`：目标明确，但不知道怎么实现；
- `CLARIFY_SPEC`：路线知道，但缺一个会显著影响结果的条件；
- `DIAGNOSE`：已经执行过，但结果不对；
- `RECOVER_CONTEXT`：多轮修改把上下文越聊越乱。

## v0.3 最大变化：三个硬门槛

### 1. Path Gate

如果目标明确，但是实现路线还不清楚，而且做错会浪费积分、时间或大量返工，**禁止直接开工**。

AI 应该先研究/解释可行路线，再决定怎么做。

### 2. Critical Unknown Gate

如果还有一个 `HIGH` 级关键未知会改变执行路线、素材职责、锁定条件或成功标准，**禁止高成本执行**。

但是不会为了低价值细节不停问你。

### 3. Drift Gate

以下情况出现时不允许继续“给 Prompt 加词”：

- 连续两次以同样原因失败；
- 三轮修改仍然不收敛；
- 已经纠正的问题再次出现。

此时必须进入诊断或上下文恢复。

## Canonical Task Spec

对话只是输入证据。真正执行依赖一份“当前有效需求”。

v0.3 分成两档：

### Mini Spec

适合普通复杂任务，只保存：目标、已确认、关键未知、锁定项、成功标准、下一步。

### Full Spec

适合长期项目、多素材、多阶段、付费生成、重复失败。会额外保存：当前路线、推导结论、假设、素材职责、已废弃决定、最后稳定状态等。

这样不会因为聊天越来越长，就把昨天错误的想法继续带进今天的执行。

## Attempt Ledger

对于 AI 视频这类付费又带随机性的工作，每次尝试只记录：

- 用了哪个 Spec 版本；
- 哪些素材；
- 相比上一次到底改了什么；
- 预期改善什么；
- 实际发生什么；
- 判断属于哪一层失败；
- 下一次应该改哪里。

这样可以避免“第八次生成时已经忘了前三次到底为什么失败”。

## 平台 Adapter

平台知识是插件层，不是核心。

例如 Seedance Adapter 可以知道白模、角色图、街景图各自可能承担什么控制职责；但它不能反过来替用户定义创意目标。

所有 Adapter 都应遵守统一 Contract：能力、限制、高影响输入、什么时候追问、安全默认、编译策略、常见失败、何时必须重新验证最新平台信息。

## 最重要的一句话

**用户不需要先学会如何把需求说得像一份技术文档。系统应该帮助用户发现：自己已经知道什么、不知道什么、还需要做什么决定，以及当前是否真的已经适合执行。**
